# 系统托盘统一契约 v0.2

> 状态：**草案（2026-11-16）** · 适用：所有带系统托盘的项目
> 这份文档管**行为语义与能力边界**，不管实现语言、内部结构、渲染技术。

## 0. 为什么需要契约

托盘的 Win32 API 三十年没变，但围绕它的实现细节——Explorer 重启恢复、DPI 选档、深色跟随、
V4 回调语义——**极易漏做**，而且漏了往往没有现象（键盘用户打不开菜单、Explorer 重启后图标
消失），要靠真实场景才暴露。这份契约把踩过的坑固化为编号规则（C-1 ~ C-17），任何语言的实现
都可以对照自查；[API-COVERAGE.md](API-COVERAGE.md) 是逐 API 的能力对照表。

## 1. 场景与能力边界

### 1.1 托盘解决什么问题

只有一件事：**让没有窗口的常驻进程变得「看得见、点得到、停得掉」。**

| 场景 | 形态 | 判据 |
|---|---|---|
| 隐身服务遥控 | 启动 / 停止 / 重启 | 服务由计划任务或自启动拉起，无窗口、无终端 ⇒ 托盘是唯一入口 |
| 环境状态可见 | 状态行 + 语义色点 | 不开任何界面就知道跑没跑 |
| 高频开关 | 勾选项 `Checked` | 一天切好几次，比开界面快 |
| 多层级选择 | 子菜单 `Children` | 选项多到一级放不下 |
| 一键动作 | 普通菜单项 + 快捷键文本 | 值得为它单开一项 |
| 通知与引导 | 气泡 `Balloon` | 图标被折进 ^ 溢出区时告诉用户去哪找 |
| 开发者运维 | 切环境 / 打开日志 | 只对开发者有意义，交付形态要能裁掉 |

### 1.2 不该放托盘的

| 不该放 | 原因 |
|---|---|
| 需要输入参数的操作 | 托盘没有输入控件，硬塞就是「点开一个对话框」 |
| 需要看大量信息的 | 那是管理台 / 主界面的职责，托盘只给「状态 + 一句话动作」 |
| 一对多管理 | 托盘是单图标单实例，多目标管理应开界面 |
| 低频配置 | 稀释高频操作，见下条 |

### 1.3 菜单分组（硬规矩）

- 高频项必须留在第一层（停/启、开关加速）
- 低频项收进子菜单（节点选择、地区选择）
- **一级菜单项（不含分隔线）建议 ≤ 12 项**，超过就该分层或移走
- 分隔线只用于语义分组，不要拿来凑间距
- 状态行固定在最上方、恒为禁用态

## 2. 能力清单

### 2.1 必需（内核必须提供，缺一项不算合格实现）

| 能力 | 语义 |
|---|---|
| 托盘图标 | 由**项目提供**图标字节（`[]byte`，.ico 含 16/24/32/48 四档），内核不内置图标 |
| Tooltip | 悬停提示，上限 **127 个 UTF-16 码元**（`szTip` 为 128 `WCHAR` 含结尾），超长必须截断而非溢出 |
| 动态 Tooltip | 运行时更新，不重建图标 |
| 菜单 | 每次右键**重新求值**（见 C-1） |
| 点击回调 | 回调给出菜单项 ID，由项目分派动作 |
| 左键回调 | 图标左键单击 / 双击 |
| 单实例 | 同一时刻只允许一个托盘进程持有图标 |
| Explorer 重启恢复 | **必做**（见 C-7），这是三份 Go 实现全缺的一项 |
| 未就绪回调 | 图标成功挂上通知区后回调一次（用于落日志、弹引导通知） |

### 2.2 可选（项目需要就要，不需要不许强塞）

| 能力 | 说明 |
|---|---|
| 气泡通知 | Windows `NIF_INFO` / macOS 通知中心 / Linux `org.freedesktop.Notifications` |
| 勾选项 | `Checked`，用于「当前生效的是哪个」 |
| 禁用项 | `Disabled`，见 C-5 |
| 子菜单 | `Children`，见 C-12 |
| 状态色点 | 状态行左侧语义色点（运行 / 警告 / 停止），见 C-13 |
| 快捷键提示 | 菜单项右侧的快捷键文本（如 `Ctrl+Alt+S`）。项目给 `Accel` 字段，**库负责拼 `\t` 让系统右对齐**；不许在 Label 里手拼 `\t` |
| 自绘菜单 | 仅 Windows 可行（见 §4），非 Windows 必须降级原生 |
| 主题适配 | 跟随系统亮/暗 |
| 预览与自查 | 弹菜单做观感验收、打印当前菜单结构 |

### 2.3 禁止

- 托盘内核里出现业务概念（端口号、服务名、任务名、URL）
- 内核自己发网络请求
- 内核弹「更新提示」「广告」 —— 托盘不是通知渠道
- 内核持有被管理进程的生命周期（托盘挂了服务照跑，服务停了托盘照在）

### 2.4 暂不支持（不是遗漏，是当前判定不做）

写清楚是为了防止反复被问「为什么没有 X」—— 每一条都有触发条件，条件到了就重开。

| 能力 | 现状 | 理由 | 什么条件下重开 |
|---|---|---|---|
| **菜单项图标** | 不支持 | ① 目前零消费者 ② 原生菜单要 `SetMenuItemInfo(MIIM_BITMAP)` + 自建 HBITMAP，高 DPI 还要按 `SM_CXSMICON` 出多档 ③ Qt 里是 `action->setIcon()` 一行，手搓不是 | 有真实需求 |
| **过渡动画** | 无 | 原生菜单由系统绘制、玻璃菜单是静态绘制，两者都没有过渡帧 —— 托盘菜单停留不到 2 秒，加动画收益极小 | 不重开 |
| **菜单项 tooltip** | 无 | 系统菜单不支持项级 tooltip，只有整个图标的 tooltip | 不重开（平台限制） |
| **全局热键注册** | 无 | 与托盘无关，是独立能力 | 有真实需求时立 `pkg/hotkey` |

**玻璃菜单（`StyleGlass`）的能力边界**：**不支持子菜单**（菜单树里出现
`Children` 时整份降级为原生并记日志），**不支持快捷键列**（`Accel` 被忽略）。需要这两项就得用
`StyleNative` —— 不要试图两套混排，那会出现两种交互手感。

**快捷键提示（Accel）是支持的**（见 §2.2）：项目给 `Accel` 字段，库拼 `\t` 右对齐 ——
**不许在 Label 里手拼 `\t`**，否则同一份菜单会出现两种对齐（`ValidateMenu` 会拦）。

## 3. 行为语义（编号规则，评审时按号引用）

**C-1 菜单每次弹出重新求值。**
`Menu()` 在每次右键时调用，实现不得缓存菜单结构。这样「运行中 / 已停止」能实时反映。

**C-2 菜单构建禁止 IO、子进程、网络。**
每次右键都会调用 `Menu()`。早期实现实测：右键里跑一次 `netstat` 往返，菜单就卡成「点了没反应」。状态必须由后台轮询缓存提供，`Menu()` 只读缓存。

**C-3 回调禁止阻塞消息泵。**
`OnMenu` / `OnOpen` 在 UI 线程上执行。启停服务这类耗时动作必须起 goroutine，并**立刻**把 tooltip 改成「正在…」。耗时阈值按 50ms 把握。

**C-4 ID 全树唯一，0 保留。**
`0` 留给「没有选中」（`TrackPopupMenu` 点空白返回 0）。子菜单内的 ID 与父层共享同一命名空间，建议按区间分配（一级 1–99、节点 200+、地区 300+）。

**C-5 禁用项：可见、不可点、不报错。**
`Disabled` 项点击必须被吞掉（不触发回调），悬停不出现高亮。**危险动作必须在非预期状态下禁用**，这不是体验优化：
- 「重启服务」在端口被其它进程占用时必须禁用 —— 停止逻辑会按端口 PID 补杀，会误杀别人的进程
- 「打开主界面」在服务未运行时必须禁用 —— 打开必然是错误页
- 同一个动作只能有一个入口（曾出现「切到常驻」同时挂在动态项和固定项上，菜单出现两行）

**C-6 单实例。**
用命名互斥量（Windows）或等价机制。第二个实例启动时不得出现第二个图标，应打印一句人话退出。

**C-7 Explorer 重启必须重挂图标。**
`explorer.exe` 重启（系统更新、shell 崩溃）会带走所有 `Shell_NotifyIcon` 注册的图标，**进程还活着但图标永久消失** —— 保活任务救不了（它只看进程死活）。正确做法：
1. `RegisterWindowMessage("TaskbarCreated")`
2. 收到该消息后先 `NIM_DELETE` 清残留（旧 shell 的记录已消失，直接 ADD 可能返回失败）
3. 再 `NIM_ADD` 重新挂上

**C-8 图标按 DPI 选档，且实现必须自己声明 DPI 感知。**
按 `SM_CXSMICON`（100% DPI 为 16，150% 为 24，200% 为 32）选对应档位，禁止一律 48px 交给系统缩 —— 会糊。

**前提是进程声明过 DPI 感知**（`SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`，失败回落 `SetProcessDPIAware`）。不声明时进程是 DPI-unaware，`GetSystemMetrics` **恒返回 96dpi 的值 16px** —— 选档逻辑等于失效，150% 屏上图标被拉伸 1.5 倍。

> 实测（2026-11-16，150% DPI 屏）：未声明 DPI 感知 → 日志「系统目标 16px」；声明后 → 「系统目标 24px」。

**图标文件应含 16 / 24 / 32 / 48 四档**，不是三档。只有 16/32/48 时，150% DPI（目标 24）只能取 32 缩到 24（1.33 倍，仍轻微发虚）。

**C-9 通知必须节流。**
进程被保活机制反复拉起时，每次都弹通知就是骚扰。至少 24h 内只弹一次，时间戳落盘（托盘重启后内存归零，只有落盘才是真的「一天一次」）。时间戳在未来或不可解析时按「没弹过」处理，宁可多弹一次不要永久静默。

> Go 侧用 `tray.NewThrottle(path, 24*time.Hour).Allow()` 即可，不必各写一份；其他语言照同一语义（落盘 + 两种异常按「没弹过」）。

**C-10 Shell 调用要能扛失败。**
`Shell_NotifyIcon` 内部会 `SendMessageTimeout`，最长阻塞 4 秒。启动注册失败时按退避重试（4s 起，指数增长，限次数），且**重试必须跑在独立线程**，不许堵住消息泵。

**C-11 退出项由项目决定。**
服务还在跑、图标却没了是半截状态 ⇒ 服务型托盘**建议不提供「退出」**，只提供「停止服务」。纯工具型（如熄屏工具）可以提供退出。

**C-12 空子菜单不得生成。**
`Children` 为空时必须生成普通项或直接不生成。空子菜单在 Windows 上显示成一条点了没反应的灰条。

**C-13 状态色点语义固定。**
运行 = 绿 · 警告/异常 = 琥珀 · 停止 = 灰。具体 RGB 由实现按亮/暗主题映射（暗色用亮色、亮色用深色），但语义不许挪用。**颜色不能是唯一的信息载体**（见 §4 降级规则）。

**色点与勾选互斥**：`Dot` 用于状态行（表示「现在什么状态」，通常配 `Disabled`），
`Checked` 用于选项（表示「选中了哪个」）。同时设置会出现 ✓ 与 ● 叠在一起、文字被推右
（2026-11-16 截图发现）。`ValidateMenu` 会拦，玻璃引擎也会兜底（有勾选就不画点）。

**C-14 显示器变化后按新 DPI 重选图标档。**
收到 `WM_DISPLAYCHANGE`（换屏 / 改缩放 / 分辨率变化）后必须重新 `GetSystemMetrics(SM_CXSMICON)` 并替换 HICON。
笔记本 150% + 外接 100% 是常见组合，不重选就是「32px 档缩到 16 糊」或「16px 档拉到 32 虚」。
重选走 goroutine（里面要调 `Shell_NotifyIcon`，可能阻塞消息泵）。

**C-15 菜单标签里不许手拼 `\t`，快捷键走 `Accel` 字段。**
手拼的后果是同一份菜单出现两种对齐，且换平台/换渲染引擎时 `\t` 的语义不一定还是列分隔。
`ValidateMenu` 会拦。

**C-16 必须切到 V4 回调语义（`NIM_SETVERSION`），且失败要退回 V0。**
不升 V4 时 `NIN_KEYSELECT` **不发送** —— 键盘用户在 `Win+B` 里选中图标按 Enter 完全没反应，
而这条路径在鼠标用户身上永远暴露不出来（可达性缺陷都是这么藏住的）。
V4 下 `lParam` 低 16 位是事件码、高 16 位是图标 ID；单击是 `NIN_SELECT`、右键是 `WM_CONTEXTMENU`。
升级失败必须退回 V0 并记日志 —— 绝不能因为升级失败让右键直接失效。
通知点击（`NIN_BALLOONUSERCLICK`）同样只有 V4 才有，应接到 `OnBalloonClick`。

**C-17 菜单必须跟随系统明暗 —— 原生菜单不会自己变。**
Win32 的 `TrackPopupMenu` **默认恒为浅色**，哪怕系统是深色模式：深色任务栏配白菜单，很突兀。
要让菜单变深必须调 `uxtheme.dll` 的未文档化导出（只按序号导出，没有名字）：
`SetPreferredAppMode`（序号 135，参数 `ForceDark`=2）+ `FlushMenuThemes`（序号 136），
且**必须在创建任何窗口之前**调用。

判断明暗读注册表 `AppsUseLightTheme`（管 Win32 应用与菜单），**不是** `SystemUsesLightTheme`
（管任务栏/开始菜单）—— 两者可以不一致，读错了就会出现「任务栏深了、菜单还按浅色处理」。

**启动时设一次不够**：菜单主题在进程内有缓存，用户切了主题不重启进程就不会变。
必须监听 `WM_SETTINGCHANGE` / `WM_THEMECHANGED`，收到后**按当前系统状态重新应用**
（显式 `ForceDark` / `ForceLight`）+ `FlushMenuThemes`。

**不要用 `AllowDark`**：语义是「允许深色」，实测表现不对称 —— 深→浅能跟随，浅→深不变。

取不到导出时静默退回浅色（功能不受影响，只是不变色），并记日志。
> Go 侧注意：不能用 `windows.NewProc("#135")` —— 那会把 `#135` 当函数名交给 `GetProcAddress`；
> 必须把序号当指针值传（等价 C 的 `MAKEINTRESOURCE(135)`）。

## 4. 平台能力矩阵与降级规则

| 能力 | Windows | macOS | Linux（SNI） |
|---|---|---|---|
| 机制 | `Shell_NotifyIcon` | `NSStatusItem`（菜单栏） | D-Bus `StatusNotifierItem` |
| 菜单由谁渲染 | 可自绘（分层窗口 ULW） | **系统渲染 NSMenu** | **桌面环境渲染 DBusMenu** |
| 图标 | 16/24/32/48 四档 | 22pt 单色 template | 22×22 PNG → ARGB32（网络字节序） |
| Tooltip | ✓ | ✓ | **GNOME 不支持**（AppIndicator 扩展原话：Not implemented） |
| 气泡通知 | ✓ `NIF_INFO` | 通知中心（macOS 13+ 需用户授权） | `org.freedesktop.Notifications` |
| 深色适配 | 手动读注册表 + `WM_SETTINGCHANGE` | template 图自动反色 | 桌面环境处理 |
| 自绘菜单 | ✓ | ✗ | ✗ |
| 状态色点 | ✓ 自绘 | ✗（模板图单色） | ✗（菜单项无装饰能力） |

### 降级规则（写文案时必须遵守）

1. **菜单文字必须自解释**，不许把关键信息只放 tooltip —— Linux/GNOME 上没有 tooltip
2. **状态不能只靠颜色** —— macOS 模板图是单色蒙版，色点不可用 ⇒ 必须有文字状态（如「运行中 · :8080」）
3. **子菜单层级 ≤ 2 层** —— Linux DBusMenu 深层嵌套体验差
4. 非 Windows 平台**一律降级系统原生菜单**，不试图复刻自绘观感

> 现状：当前实现仅支持 Windows，非 Windows 走返回 `ErrUnsupported` 的桩。
> 被管理的服务本身往往强绑 Windows（计划任务、hosts、锁屏 API、Win32 热键），托盘跨平台了也没有可管理的对象。

### 无障碍与动效立场

| | `StyleNative` | `StyleGlass`（自绘） |
|---|---|---|
| 屏幕阅读器（UIA） | ✅ 系统菜单，读得到 | ❌ 纯位图，读到空气 |
| 键盘导航 | ✅ 系统实现（↑↓ / Esc / 首字母跳转） | ⚠️ 手写，覆盖不全 |
| 过渡动效 | ❌ 无（动效归系统，库不干预） | ✅ 可自绘（若实现） |
| 高对比度 / 放大镜 | ✅ 系统跟随 | ⚠️ 需自行处理 |

**结论：投政企 / 等保场景必须用 `StyleNative`。** 这不是偏好问题 —— 自绘位图对辅助技术是黑盒，
验收时会被直接判不合格。

**动效不是缺陷**：托盘菜单是「瞬时小面板」，用户停留不到 2 秒，系统原生菜单不做过渡动画是
Windows 的设计选择，不是库的缺失。

## 5. 验收清单

每个实现在发版前逐条过，不通过不发：

- [ ] 图标出现在通知区（Win11 会被折进 ^ 溢出区，需确认能找到）
- [ ] tooltip 内容与当前状态一致，超长被截断而非溢出
- [ ] 右键菜单项数量、禁用态、勾选态与当前状态匹配
- [ ] 菜单在服务运行 / 停止 / 端口被占 三种状态下都正确
- [ ] 启动第二个实例不会出现第二个图标
- [ ] 重启 `explorer.exe` 后图标自动回来（C-7）
- [ ] 150% DPI 下图标不糊（C-8）
- [ ] 换到另一块不同缩放的显示器后图标仍清晰（C-14）
- [ ] 带快捷键的菜单项右对齐显示、不与标签粘连（C-15）
- [ ] `Win+B` 选中图标后按 Enter 能弹出菜单（C-16 的键盘可达性）
- [ ] 系统深色模式下菜单是深色的（C-17；Win32 默认不会变）
- [ ] 连续重启托盘进程 3 次，通知不超过 1 条（C-9）
- [ ] 点「停止服务」后，菜单里所有会导致错误页或误杀的动作都已禁用（C-5）
- [ ] 菜单打开耗时 < 100ms（C-2 的反向检查：把 `Menu()` 打点计时）
- [ ] 托盘退出/崩溃不影响被管理的服务

## 6. 变更流程
